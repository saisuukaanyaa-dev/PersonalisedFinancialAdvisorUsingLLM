Big picture

Architecture

Three containers on one Docker network. The app is a FastAPI service that does everything the n8n canvas did: pages, intake, calculations, AI calls, reports and chat. Postgres + pgvector holds accounts, profiles, reports, chat history and the knowledge-base vectors. market-analyzer is the same NIFTY 50 history API as v3.2. OpenAI and Google are the only outside services.

The core idea: numbers come from code, words come from AI. v3.2 established this rule. The Python edition uses it for speed as well as correctness: the numbers and charts never wait for AI. The report opens as soon as the maths is done, and the AI explanation is swapped in when it's ready.

Stock screen in code engine/stocks.py · screen
def screen(rows: list[dict], rules: dict | None, limit: int = 5) -> dict:
    if not rules:
        return {"picks": [], "screened": len(rows), "passed": 0}
    passed = []
    for s in rows:
        dd, vol, cagr = s.get("max_drawdown_pct"), s.get("annualized_volatility_pct"), s.get("cagr_pct")
        if not all(isinstance(x, (int, float)) for x in (dd, vol, cagr)):
            continue
        if -abs(dd) < rules["max_drawdown_pct"] or vol > rules["max_volatility_pct"]:
            continue
        if cagr < vol * rules["min_cagr_to_volatility"]:
            continue
        passed.append(s)
    # best growth per unit of swing first; never more than N per sector
    passed.sort(key=lambda s: s["cagr_pct"] / max(s["annualized_volatility_pct"], 1), reverse=True)
    picks, per_sector = [], {}
    for s in passed:
        sec = str(s.get("sector") or "").lower()
        if per_sector.get(sec, 0) >= rules["max_per_sector"]:
            continue
        per_sector[sec] = per_sector.get(sec, 0) + 1
        picks.append({
            "symbol": s["symbol"], "company_name": s.get("company_name"), "sector": s.get("sector"),
            "five_year_cagr_pct": round(s["cagr_pct"], 1),
            "annualized_volatility_pct": round(s["annualized_volatility_pct"], 1),
            "max_drawdown_pct": round(s["max_drawdown_pct"], 1),
            "rationale": (f"Grew about {s['cagr_pct']:.0f}% a year with {s['annualized_volatility_pct']:.0f}% yearly swings; "
                          f"its worst fall (▼{abs(s['max_drawdown_pct']):.0f}%) is within your limit."),
        })
        if len(picks) >= limit:
            break
    return {"picks": picks

def check_chat_input(message: str) -> str | None:
    """None if the message may go to the AI; otherwise a kind refusal."""
    m = str(message or "").strip()
    if not m:
        return "Ask me anything about your plan - for example \"What if I invest 30K a month?\""
    if len(m) > 1500:
        return "That's a long message - could you ask it in a sentence or two?"
    pii = find_pii(m)
    if pii:
        return (f"Please don't share ID or account numbers here (I spotted what looks like a {pii[0]}). "
                "I don't need them to help with your plan.")
    if looks_like_injection(m):
        return "I can only help with your personal finance plan - ask me about your goal, savings, loans or investments."
    return None

async def google_callback(request: Request, code: str = "", state: str = "", error: str = ""):
    expected = request.session.pop("oauth_state", None)
    if error or not code or not expected or not hmac.compare_digest(state, expected):
        return RedirectResponse("/login?error=google_failed", 303)
    try:
        async with httpx.AsyncClient(timeout=15) as client:

                "code": code, "client_id": settings.google_client_id, "client_secret": settings.google_client_secret,
                "redirect_uri": _redirect_uri(), "grant_type": "authorization_code"})
            tok.raise_for_status()
            info = await client.get(GOOGLE_USERINFO, headers={"Authorization": f"Bearer {tok.json()['access_token']}"})
            info.raise_for_status()
            u = info.json()
    except (httpx.HTTPError, KeyError, ValueError):
        return RedirectResponse("/login?error=google_failed", 303)
    email = str(u.get("email") or "").lower()
    if not u.get("sub") or not email or not u.get("email_verified"):
        return RedirectResponse("/login?error=google_unverified", 303)
    row = await db.fetchone("SELECT id FROM accounts WHERE google_sub = %s", u["sub"])
    if not row:
        # Link to an existing email account, or create one. Password sign-ups don't prove the person owns
        # the address, but Google does - so on linking, the Google owner takes over and any password
        # set by whoever registered the address first stops working.
        row = await db.fetchone(

               RETURNING id""", email, (u.get("name") or "")[:80] or None, u["sub"])

How the app measures it

  • Every OpenAI response includes a usage block. llm._post records it into the current meter: tokens in, cached, out, reasoning, and time.
  • A meter is a context variable, so each plan's background task and each chat question has its own, even when many run at once.
  • The plan's usage is saved on its report; a chat answer's usage is saved on the answer row. A what-if is costed twice: the chat reply, and the new plan it creates.
  • People see it on each report ("AI cost of this plan ₹0.37 · 2 AI calls + 1 search · 6,778 tokens"), under each chat answer, and on the Usage page. For the team, ./scripts/usage-report.sh prints plans, ₹ per plan, questions and ₹ per question for every user.
  • Prices and the rupee rate are settings in .env (PRICE_…_PER_M, USD_TO_INR).
Levers if cost matters. Output tokens dominate, so shorter answers cost less. Two options: keep reasoning_effort=low, or try gpt-5-nano ($0.05 input / $0.40 output, about 5× cheaper) for the chat. Keeping the facts block first in both calls maximises prompt caching.

Accounts and privacy

Sign-in and safety

  • Email + password: scrypt hash with a per-user salt; 8 failed attempts lock that email for 15 minutes; successful sign-ins never count.
  • Google (when configured): OAuth authorisation-code flow with a random state. Only verified Google emails are accepted. Linking to an existing password account turns off the old password, because Google has proved who owns the address.
  • Sessions: signed, HTTP-only, SameSite=Lax cookie holding only the account id; 7 days.
  • CSRF: every write API needs the header X-PFA: 1, which other sites can't send without a CORS preflight this app never allows.
  • Privacy: reports and their status are visible only to their owner (others get "not found"). ID numbers in chat are refused and never stored. AI output is masked for ID numbers.
  • Page security: Content-Security-Policy allows scripts only from the app itself; no framing; no external CDNs.
  • Email + password sign-up doesn't verify the address. That's fine for local testing; a public version should use Google only or add email verification.

Preparing for review

Questions a mentor may ask

Did moving from n8n to Python change the advice?
No. The finance rules, thresholds and formulas were ported line for line from the v3.2 Code nodes and are covered by unit tests. The same Priya profile gives the same in-hand estimate, risk plan and projection.
Isn't n8n the point of the capstone?
The n8n v3.2 and v3.2.3 bundles are unchanged and still run. The Python edition answers the mentor's performance feedback, and it shows the same design mapped to code: each node became a function, as the module table shows.
Why only two AI calls when v3.2 had five agents?
The agents mostly re-explained numbers that code had already computed. With the facts fixed, the writing splits into two independent tasks that can run at the same time. Stock discovery is a deterministic filter, so it moved into code.
What if OpenAI is down?
The report still opens with every number and chart, plus explanation text written from the numbers. The chat says the AI service is unavailable.
How do you know what a user costs?
Every AI call's tokens are recorded against the plan or question that caused it and priced at the published rates. The Usage page and usage-report.sh read these records; the costs above are measured, not estimated.
How would this go to production?
Put it behind HTTPS (set COOKIE_SECURE=true), use Google-only sign-in or add email verification, use a managed Postgres with pgvector, and run more than one app worker. Background AI tasks would then move to a small job queue.
